# SANPACK Storefront Design System

Статус: рабочий источник истины для публичного магазина SANPACK. Документ описывает решения, которые должны сохраняться при доработке сайта, мобильной версии и Telegram Mini App. Админ-панель использует те же данные и базовые токены, но может иметь более плотную компоновку.

## 1. Принципы

1. Каталог — главная задача интерфейса. Главная страница сразу открывает товары и категории, поэтому отдельные ссылки «Главная» и «Каталог» в десктопном хедере не дублируются.
2. SANPACK остаётся B2B-магазином. В интерфейсе используются привычные слова «Корзина» и «В корзину», но итоговое действие называется «Отправить заявку», а сумма — «Предварительная сумма».
3. Контент важнее декора. Белые поверхности, спокойный фон, минимум рамок и только функциональные тени.
4. Один набор правил работает на desktop, mobile web и Telegram Mini App. Меняется компоновка, а не визуальный язык.
5. Все пользовательские строки локализуются на русский, узбекский и английский. Нельзя показывать технические ключи или русский fallback как готовый перевод.
6. Публичный интерфейс читает товары, категории, цены, изображения, переводы и настройки из текущего repository/API-слоя. Вёрстка не создаёт отдельный источник данных.

## 2. Информационная архитектура

### Desktop

- Хедер: логотип, широкий глобальный поиск, избранное, корзина, язык и профиль. «О компании», «Доставка» и «Контакты» находятся в футере и не конкурируют с каталогом.
- Тонкая служебная полоса: город, часы работы, один основной телефон, обратный звонок и Telegram.
- Левая колонка: каталог категорий; ниже отдельный блок «Сервисы SANPACK» с полиграфией и конструктором пакета.
- Центральная колонка: промо-карусель, популярные категории, полки товаров или выдача выбранной категории.
- Правая колонка: закреплённая корзина с предварительной суммой и условиями доставки.
- «Клиенты и партнёры» входят в страницу «О компании»; старый URL может сохраняться для совместимости.

### Mobile и Telegram Mini App

- Компактный хедер: логотип и поиск.
- Горизонтальные хабы категорий, затем двухколоночная сетка товаров.
- Основная навигация закреплена снизу.
- При непустой корзине над навигацией показывается компактный cart dock.
- Важные действия должны учитывать `safe-area-inset-*`.

## 3. Токены

Фактические значения задаются CSS-переменными в `app/globals.css`; компоненты не должны вводить собственные произвольные радиусы и цвета.

- Цвет бренда: `--sp-brand`, состояния — `--sp-brand-deep`, `--sp-brand-soft`, контрастный текст — `--sp-on-brand`.
- Фон страницы: `--sp-canvas`; основная поверхность: `--sp-surface`; вложенная нейтральная поверхность: `--sp-surface-inset`.
- Текст: `--sp-ink`, `--sp-ink-secondary`, `--sp-ink-muted`, `--sp-ink-tertiary`.
- Разделители: `--sp-line`, `--sp-line-soft`, `--sp-line-strong`.
- Радиус карточек: `--sp-radius-card`; контролов: `--sp-radius-control`; внутренних элементов: `--sp-radius-control-inner`.
- Тени: `--sp-shadow-soft` для контролов, `--sp-shadow-raised` только для закреплённых или всплывающих поверхностей.
- Фокус: `--sp-focus`; интерактивный элемент обязан иметь различимый `focus-visible`.

## 4. Типографика

- Основной интерфейс: Manrope через общий sans-stack проекта.
- Заголовки: тот же шрифт, увеличенная насыщенность и слегка отрицательный tracking.
- Фирменный extended-шрифт допускается только внутри логотипа и специальных брендовых материалов; не использовать для длинных заголовков и элементов управления.
- Минимальный размер интерактивной подписи — 12 px, основного текста — 14 px.

## 5. Изображения

### Иконки категорий в навигации

- Каждая категория имеет самостоятельный файл; запрещены общие коллажи и нарезка спрайта.
- Фотография строго сверху, камера перпендикулярна поверхности.
- Фон — чистый `#FFFFFF`; объект по центру, полностью в кадре, с заметным свободным полем.
- Допускается мягкая компактная контактная тень, не доходящая до границ.
- Никаких надписей, логотипов, брендов, водяных знаков, перспективы и изометрии.
- Рабочий набор: `public/catalog/category-icons-v3/*.webp`, 512×512, WebP quality 90, без кадрирования.

### Популярные категории

- Каждый горизонтальный tile использует отдельное широкое изображение, а не увеличенную квадратную иконку и не фрагмент общего коллажа.
- Левая часть композиции остаётся спокойной и свободной для названия; продукция собрана справа.
- Фон чистый белый или очень светлый нейтральный, яркость товара естественная, без текста, логотипов и водяных знаков внутри изображения.

### Товары

- Используется реальное изображение из данных товара.
- Контейнер и изображение имеют один радиус и `overflow-hidden`; фон изображения белый или нейтральный.
- `object-contain` обязателен для упаковки и предметной фотографии, чтобы товар не обрезался.
- Если изображения нет, показывается локализованное сообщение о том, что фотография появится позже; технический placeholder бренда не используется.

## 6. Компоненты

### Product card

- Порядок: изображение → цена → название → минимальный заказ.
- Сердце и плюс используют квадрат 44×44 px, один радиус, тень, border/ring и иконку 20×20 px.
- Контролы располагаются внутри изображения: избранное справа сверху, корзина справа снизу.
- Карточка не получает тяжёлую внешнюю рамку; кликабельные зоны не должны конфликтовать.

### Category tile

- Белый фон совпадает с фоном изображения, поэтому у фотографии не читается прямоугольная граница.
- Внешний контейнер обрезает содержимое по `--sp-radius-card`.
- Название и количество товаров остаются читаемыми поверх лёгкого белого градиента.

### Promo carousel

- Каждый баннер — самостоятельный bento-блок на всю ширину центральной колонки.
- Слайды прокручиваются горизонтально и циклически; поддерживаются swipe, кнопки, клавиатура и `prefers-reduced-motion`.
- Стрелки не выходят за viewport на промежуточной ширине.

### Header

- Не дублирует каталог, который уже является главной страницей.
- На desktop информационные страницы не выводятся в основном хедере; они доступны из футера.
- Сервисные модули находятся в левом каталожном меню.
- Верхняя полоса показывает только оперативные контакты и не конкурирует с поиском.

### Product page

- Mobile: edge-to-edge галерея сразу под хедером; кнопки назад и увеличения поверх фото; затем название, краткое описание, варианты, избранное, раскрываемая подробная информация и рекомендации.
- Desktop: крупный заголовок, большая открытая галерея без тяжёлой карточной рамки и единая информационно-коммерческая колонка с ценой, вариантом, количеством и действием.
- Цена и действие закрепляются над нижней навигацией на mobile.
- Для B2B явно показываются минимальная партия, единица продажи, скидки от объёма, предварительная сумма, наличие и связь с менеджером.

## 7. Адаптивность

- `< 768 px`: mobile shell, две карточки в ряд, без desktop sidebar/cart.
- `768–1023 px`: планшетная выдача, desktop-поиск, фильтры в sheet.
- `1024–1279 px`: левая колонка + контент.
- `≥ 1280 px`: левая колонка + контент + правая корзина.
- Проверочные viewport: 375×812, 390×844, 844×390, 1440×900.
- На каждом viewport `document.scrollWidth <= window.innerWidth`.

## 8. Доступность и поведение

- Минимальная интерактивная зона — 44×44 px.
- Иконки без текста имеют `aria-label` и `title`, если смысл не очевиден из контекста.
- Текущий пункт навигации отмечается `aria-current`; переключатели — `aria-pressed`.
- Карусель управляется стрелками клавиатуры и останавливает автопрокрутку при hover/interaction.
- Цвет не является единственным способом показать состояние.
- Нельзя убирать outline без равноценного `focus-visible`.

## 9. Контент, backend и admin

- Категории, товары, локализованные поля, цены и статусы поступают из Firestore через существующие repository/API abstractions.
- Админ-панель остаётся местом управления этими полями. Новая витрина не дублирует сущности в локальных константах, кроме презентационных соответствий (например, category artwork map).
- Изменения схемы данных должны быть обратно совместимыми либо сопровождаться миграцией и проверкой Telegram-бота.
- Корзина и заявка используют текущий `RequestCartContext`; отправка заказа и уведомление боту не должны менять контракт без отдельной проверки.

## 10. Definition of Done для интерфейсной правки

1. Строки проверены на RU, UZ и EN.
2. Нет горизонтального overflow на четырёх контрольных viewport.
3. Контролы используют общие токены и имеют 44×44 px touch target.
4. Изображения не обрезаны и имеют корректный fallback.
5. Проверены keyboard focus и reduced motion для интерактивных элементов.
6. Выполнены `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`, `git diff --check`.
7. Не выполнялись production-записи, deploy или изменение данных Firestore.
